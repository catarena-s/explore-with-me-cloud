# Архитектура проекта Explore With Me Cloud

## Основные модули и их ответственность

### Инфраструктурные модули

#### 1. **git-config** (Config Server)
- **Порт:** 8888
- **Ответственность:** Централизованное управление конфигурациями всех микросервисов
- **Функции:**
  - Получение настроек из Git-репозитория
  - Распределение конфигураций между сервисами
  - Поддержка профилей окружений

#### 2. **server** (Eureka Server)
- **Порт:** 8761
- **Ответственность:** Сервис-реестр для регистрации и обнаружения микросервисов
- **Функции:**
  - Регистрация всех микросервисов при старте
  - Обнаружение сервисов для межсервисного взаимодействия
  - Мониторинг состояния сервисов

#### 3. **gateway** (API Gateway)
- **Порт:** 8765
- **Ответственность:** Единая точка входа для всех клиентских запросов
- **Функции:**
  - Маршрутизация запросов к соответствующим микросервисам
  - Балансировка нагрузки между инстансами сервисов
  - Централизованная обработка запросов

#### 4. **ewm-keycloak**
- **Порт:** 8181
- **Ответственность:** Управление аутентификацией и авторизацией
- **Функции:**
  - Интеграция с Keycloak для OAuth2
  - Управление пользователями и ролями
  - Выдача JWT-токенов

### Бизнес-модули (ewm-main)

#### 5. **ewm-users** (Сервис пользователей)
- **Ответственность:** Управление пользователями системы
- **Функции:**
  - Регистрация и управление профилями пользователей
  - Хранение информации о пользователях
  - Интеграция с Keycloak для аутентификации
- **База данных:** `ewm_users`
- **Основные таблицы:** `users`

#### 6. **ewm-event** (Сервис мероприятий)
- **Ответственность:** Управление мероприятиями и категориями
- **Функции:**
  - Создание, редактирование и публикация событий
  - Управление категориями мероприятий
  - Управление локациями
  - Поиск и фильтрация событий
  - Интеграция со статистикой просмотров
- **База данных:** отдельная БД для событий
- **Основные таблицы:** `events`, `categories`, `locations`

#### 7. **ewm-request** (Сервис запросов)
- **Ответственность:** Управление запросами на участие в мероприятиях
- **Функции:**
  - Создание запросов на участие
  - Подтверждение/отклонение запросов организаторами
  - Управление статусами запросов
  - Отправка уведомлений через RabbitMQ
- **База данных:** отдельная БД для запросов
- **Основные таблицы:** `requests`

#### 8. **ewm-compilation** (Сервис подборок)
- **Ответственность:** Управление подборками мероприятий
- **Функции:**
  - Создание и редактирование подборок
  - Добавление мероприятий в подборки
  - Публикация подборок
- **База данных:** отдельная БД для подборок
- **Основные таблицы:** `compilation`, `compilation_events`

#### 9. **ewm-subscription** (Сервис подписок)
- **Ответственность:** Управление подписками и дружбой между пользователями
- **Функции:**
  - Подписка на других пользователей
  - Управление запросами на дружбу
  - Получение списка друзей
  - Интеграция с событиями друзей
- **База данных:** отдельная БД для подписок
- **Основные таблицы:** `friendship`

#### 10. **ewm-notification** (Сервис уведомлений)
- **Ответственность:** Хранение и управление уведомлениями
- **Функции:**
  - Получение уведомлений из RabbitMQ
  - Хранение истории уведомлений
  - Предоставление API для просмотра уведомлений
- **База данных:** отдельная БД для уведомлений
- **Основные таблицы:** `notification`

#### 11. **ewm-stats** (Сервис статистики)
- **Ответственность:** Сбор и анализ статистики просмотров
- **Функции:**
  - Сохранение информации о просмотрах событий
  - Предоставление статистики по популярности событий
  - Аналитика использования API
- **База данных:** отдельная БД для статистики
- **Основные таблицы:** `endpoint_hits`

### Общие модули

#### 12. **ewm-dto**
- **Ответственность:** Общие DTO (Data Transfer Objects) для межсервисного взаимодействия
- **Содержит:**
  - DTO для всех основных сущностей (Event, User, Request, Compilation и т.д.)
  - DTO для RabbitMQ сообщений
  - Общие enum-типы
- **Использование:** Импортируется всеми микросервисами для единообразного обмена данными

#### 13. **ewm-utils**
- **Ответственность:** Общие утилиты и инфраструктурные компоненты
- **Содержит:**
  - Обработчики исключений (`ApiExceptionHandler`, `ApiFeignExceptionHandler`)
  - Кастомные исключения (`NotFoundException`, `ConflictException`, `ValidateException` и т.д.)
  - Утилиты для RabbitMQ (`RabbitSupplier`)
  - Конвертеры для Keycloak (`KCRoleConverter`)
  - Общие константы
- **Использование:** Импортируется всеми микросервисами

## Ключевые сущности

### Доменные модели

#### **User** (ewm-users)
- `id` - уникальный идентификатор
- `email` - электронная почта (уникальная)
- `name` - имя пользователя
- `uid` - идентификатор из Keycloak
- `autoSubscribe` - автоматическая подписка на события

#### **Event** (ewm-event)
- `id` - уникальный идентификатор
- `title` - название события
- `annotation` - краткое описание
- `description` - полное описание
- `paid` - платное/бесплатное участие
- `eventDate` - дата и время проведения
- `category` - категория (связь с Category)
- `initiatorId` - идентификатор организатора
- `location` - локация (связь с Location)
- `participantLimit` - ограничение на количество участников
- `confirmedRequests` - количество подтвержденных заявок
- `state` - состояние события (PENDING, PUBLISHED, CANCELED)
- `createdOn` - дата создания
- `publishedOn` - дата публикации

#### **Category** (ewm-event)
- `id` - уникальный идентификатор
- `name` - название категории

#### **Location** (ewm-event)
- `id` - уникальный идентификатор
- `lat` - широта
- `lon` - долгота

#### **Request** (ewm-request)
- `id` - уникальный идентификатор
- `requesterId` - идентификатор пользователя-заявителя
- `eventId` - идентификатор события
- `status` - статус запроса (PENDING, CONFIRMED, REJECTED, CANCELED)
- `created` - дата создания
- `isPrivate` - приватность запроса

#### **Compilation** (ewm-compilation)
- `id` - уникальный идентификатор
- `title` - название подборки
- `pinned` - закреплена ли подборка

#### **CompilationEvent** (ewm-compilation)
- Связующая таблица между подборками и событиями
- `compilationId` - идентификатор подборки
- `eventId` - идентификатор события

#### **Friendship** (ewm-subscription)
- `id` - уникальный идентификатор
- `followerId` - идентификатор подписчика
- `userId` - идентификатор пользователя, на которого подписались
- `state` - состояние дружбы (PENDING, CONFIRMED, REJECTED)
- `createdOn` - дата создания

#### **Notification** (ewm-notification)
- `id` - уникальный идентификатор
- `userId` - идентификатор получателя
- `message` - текст уведомления
- `type` - тип сообщения
- `created` - дата создания

## Архитектурные ограничения

### 1. Микросервисная архитектура
- **Принцип:** Каждый сервис имеет свою отдельную базу данных
- **Ограничение:** Запрещено прямое обращение к БД другого сервиса
- **Причина:** Обеспечение независимости сервисов и возможности их независимого масштабирования

### 2. Межсервисное взаимодействие
- **Синхронное взаимодействие:** Только через OpenFeign с OAuth2 аутентификацией
- **Асинхронное взаимодействие:** Только через RabbitMQ
- **Ограничение:** Запрещены прямые HTTP-вызовы между сервисами без использования Feign
- **Причина:** Централизованное управление аутентификацией и обработкой ошибок

### 3. Единая точка входа
- **Принцип:** Все внешние запросы проходят через API Gateway
- **Ограничение:** Клиенты не должны обращаться напрямую к микросервисам
- **Причина:** Централизованная маршрутизация, балансировка нагрузки и безопасность

### 4. Конфигурация
- **Принцип:** Все настройки хранятся в Config Server
- **Ограничение:** Запрещено хардкодить конфигурации в коде
- **Причина:** Централизованное управление настройками и поддержка разных окружений

### 5. Безопасность
- **Принцип:** Все сервисы используют OAuth2 Resource Server с JWT-токенами от Keycloak
- **Ограничение:** Запрещено обходить механизмы безопасности
- **Причина:** Единообразная система авторизации и контроля доступа

### 6. Общие модули
- **Принцип:** DTO и утилиты вынесены в отдельные модули (ewm-dto, ewm-utils)
- **Ограничение:** Запрещено дублировать DTO и утилиты в разных сервисах
- **Причина:** Обеспечение консистентности данных и переиспользования кода

### 7. Управление данными
- **Принцип:** Миграции БД выполняются через Liquibase
- **Ограничение:** Запрещено изменять структуру БД вручную
- **Причина:** Версионирование схемы БД и возможность отката изменений

### 8. Версионирование API
- **Принцип:** Использование DTO для версионирования API
- **Ограничение:** Изменения в DTO должны быть обратно совместимы или версионированы
- **Причина:** Обеспечение совместимости между сервисами

## Части проекта, которые нельзя менять

### 1. **Структура общих модулей (ewm-dto, ewm-utils)**
- **Что нельзя менять:**
  - Пакетная структура (`dev.shvetsova.ewmc.dto.*`, `dev.shvetsova.ewmc.exception.*`)
  - Имена классов исключений и их иерархию
  - Структуру DTO классов, используемых для межсервисного взаимодействия
  - Конвертер ролей Keycloak (`KCRoleConverter`)
- **Почему:** Эти модули используются всеми микросервисами. Изменения приведут к необходимости обновления всех зависимых сервисов и могут сломать совместимость.

### 2. **Механизм аутентификации (OAuth2 + Keycloak)**
- **Что нельзя менять:**
  - Конфигурацию OAuth2 Resource Server
  - Использование `KCRoleConverter` для конвертации ролей
  - Структуру JWT-токенов и их валидацию
  - Конфигурацию Feign клиентов с OAuth2 (`OAuthFeignConfig`)
- **Почему:** Изменения нарушат единую систему безопасности и приведут к проблемам с авторизацией во всех сервисах.

### 3. **Интеграция с Eureka Server**
- **Что нельзя менять:**
  - Регистрацию сервисов в Eureka
  - Использование имен сервисов в Feign клиентах (должны совпадать с `spring.application.name`)
  - Порты инфраструктурных сервисов (Eureka: 8761, Config Server: 8888, Gateway: 8765)
- **Почему:** Eureka используется для service discovery. Изменения приведут к невозможности обнаружения сервисов.

### 4. **Структура RabbitMQ сообщений**
- **Что нельзя менять:**
  - DTO для RabbitMQ сообщений (`RequestMqDto`, `EventInfoMq`, `NewNotificationDto` и т.д.)
  - Имена очередей и их назначение
  - Формат сообщений между сервисами
- **Почему:** Изменения сломают асинхронную коммуникацию между сервисами, которая критична для работы уведомлений и событий.

### 5. **Имена таблиц в базах данных**
- **Что нельзя менять:**
  - Имена таблиц, определенные в `@Table(name = "...")` аннотациях
  - Структуру связей между таблицами (foreign keys)
- **Почему:** Изменения потребуют миграций БД во всех окружениях и могут сломать существующие данные. Также могут нарушить работу Liquibase.

### 6. **Конфигурация Config Server**
- **Что нельзя менять:**
  - Порты инфраструктурных сервисов
  - Структуру профилей конфигурации (`micro`, `db`, `rabbit`, `kc`, `feign`)
  - Механизм получения конфигураций из Git
- **Почему:** Config Server является центральным источником конфигураций. Изменения затронут все сервисы.

### 7. **Обработка исключений**
- **Что нельзя менять:**
  - Структуру `ApiError` и формат ответов об ошибках
  - Иерархию исключений (`ApiException` → `NotFoundException`, `ConflictException` и т.д.)
  - Обработчик Feign исключений (`ApiFeignExceptionHandler`)
- **Почему:** Единообразная обработка ошибок критична для клиентов API и межсервисного взаимодействия.

### 8. **Структура пакетов в микросервисах**
- **Что нельзя менять:**
  - Базовый пакет `dev.shvetsova.ewmc.*`
  - Структуру пакетов (`model`, `service`, `controller`, `repository`, `http`, `mq`, `security`)
- **Почему:** Стандартизированная структура облегчает навигацию и поддержку кода. Изменения усложнят понимание проекта новыми разработчиками.

### 9. **Имена сервисов (spring.application.name)**
- **Что нельзя менять:**
  - Имена сервисов в `application.properties` (`ewm-users`, `ewm-event`, `ewm-request` и т.д.)
- **Почему:** Имена используются в Eureka для регистрации и в Feign клиентах для обнаружения сервисов. Изменения сломают межсервисное взаимодействие.

### 10. **Версии зависимостей в родительском POM**
- **Что нельзя менять без тестирования:**
  - Версию Spring Boot (3.1.3)
  - Версию Spring Cloud (2022.0.4)
  - Версию Java (17)
- **Почему:** Изменения версий могут привести к breaking changes и несовместимости между компонентами. Требуется полное тестирование всех сервисов.

## Рекомендации по расширению

При добавлении нового функционала:

1. **Новый микросервис:**
   - Создавать в модуле `ewm-main`
   - Использовать общие модули `ewm-dto` и `ewm-utils`
   - Регистрировать в Eureka
   - Настраивать OAuth2 аутентификацию
   - Создавать отдельную БД

2. **Новые DTO:**
   - Добавлять в модуль `ewm-dto`
   - Использовать валидацию через аннотации
   - Обеспечивать обратную совместимость

3. **Новые RabbitMQ очереди:**
   - Определять DTO для сообщений в `ewm-dto`
   - Использовать `RabbitSupplier` из `ewm-utils`
   - Документировать назначение очереди

4. **Новые Feign клиенты:**
   - Использовать `OAuthFeignConfig` для аутентификации
   - Указывать правильное имя сервиса (из Eureka)
   - Обрабатывать ошибки через `ApiFeignExceptionHandler`
