# Обзор проекта Explore With Me Cloud

## Назначение проекта

**Explore With Me Cloud** — это бэкенд-приложение для планирования событий и организации участия в различных мероприятиях. Проект построен на микросервисной архитектуре с использованием Spring Cloud и позволяет пользователям:

- Создавать и управлять мероприятиями (событиями)
- Формировать подборки мероприятий по темам
- Подавать запросы на участие в мероприятиях
- Подписываться на других пользователей и получать уведомления
- Просматривать статистику и популярные события

Проект является альтернативной реализацией монолитного приложения ["Explore With Me"](https://github.com/catarena-s/java-explore-with-me) с переходом на микросервисную архитектуру.

## Основные сценарии использования

### 1. Управление пользователями
- Регистрация новых пользователей
- Аутентификация и авторизация через Keycloak
- Управление профилями пользователей

### 2. Создание и управление мероприятиями
- Создание событий различных типов (выставки, спортивные мероприятия, походы в кино и т.д.)
- Редактирование информации о мероприятиях
- Поиск и просмотр доступных мероприятий
- Управление категориями мероприятий

### 3. Работа с подборками
- Создание тематических подборок мероприятий
- Добавление мероприятий в подборки
- Публикация и редактирование подборок

### 4. Участие в мероприятиях
- Подача запросов на участие в мероприятиях
- Подтверждение или отклонение запросов организаторами
- Управление списком участников

### 5. Социальные функции
- Подписка на других пользователей
- Получение уведомлений о событиях друзей
- Управление списком друзей

### 6. Статистика и аналитика
- Сбор статистики просмотров событий
- Анализ популярности мероприятий

## Как запустить проект локально

### Предварительные требования

Для запуска проекта вам понадобятся:

1. **Java 17** — установленная JDK
2. **Maven** — система сборки проекта
3. **PostgreSQL** — база данных (для каждого микросервиса нужна отдельная БД)
4. **RabbitMQ** — брокер сообщений для асинхронной коммуникации
5. **Keycloak** — сервер аутентификации и авторизации (опционально, можно запустить через Docker)

### Порядок запуска сервисов

Проект состоит из нескольких сервисов, которые нужно запускать в определенном порядке:

#### 1. Config Server (git-config)
**Порт:** 8888

Сервис для централизованного управления конфигурациями. Получает настройки из Git-репозитория.

```bash
cd git-config
mvn spring-boot:run
```

#### 2. Eureka Server (server)
**Порт:** 8761

Сервис-реестр для регистрации и обнаружения микросервисов.

```bash
cd server
mvn spring-boot:run
```

После запуска доступен по адресу: http://localhost:8761

#### 3. Keycloak (ewm-keycloak)
**Порт:** 8181 (по умолчанию)

Сервис аутентификации и авторизации. Можно запустить через Docker или как отдельное приложение.

```bash
cd ewm-main/ewm-keycloak
mvn spring-boot:run
```

#### 4. Микросервисы приложения

После запуска инфраструктурных сервисов можно запускать бизнес-логику:

**Сервис пользователей (ewm-users)**
```bash
cd ewm-main/ewm-users
mvn spring-boot:run
```

**Сервис мероприятий (ewm-event)**
```bash
cd ewm-main/ewm-event
mvn spring-boot:run
```

**Сервис запросов (ewm-request)**
```bash
cd ewm-main/ewm-request
mvn spring-boot:run
```

**Сервис подборок (ewm-compilation)**
```bash
cd ewm-main/ewm-compilation
mvn spring-boot:run
```

**Сервис подписок (ewm-subscription)**
```bash
cd ewm-main/ewm-subscription
mvn spring-boot:run
```

**Сервис уведомлений (ewm-notification)**
```bash
cd ewm-main/ewm-notification
mvn spring-boot:run
```

**Сервис статистики (ewm-stats)**
```bash
cd ewm-stats
mvn spring-boot:run
```

#### 5. Gateway (gateway)
**Порт:** 8765

API Gateway — единая точка входа для всех клиентских запросов.

```bash
cd gateway
mvn spring-boot:run
```

### Настройка баз данных

Каждый микросервис использует свою отдельную базу данных PostgreSQL. Имена баз данных указываются в конфигурационных файлах каждого сервиса (например, `db.name = ewm_users`).

Перед запуском убедитесь, что:
- PostgreSQL запущен
- Созданы необходимые базы данных
- Настроены права доступа

Миграции базы данных выполняются автоматически через Liquibase при старте каждого сервиса.

### Настройка RabbitMQ

Убедитесь, что RabbitMQ запущен и доступен. Настройки подключения находятся в конфигурационных файлах сервисов.

### Проверка работы

После запуска всех сервисов:

1. Проверьте Eureka Server: http://localhost:8761 — должны быть зарегистрированы все микросервисы
2. API доступно через Gateway: http://localhost:8765
3. Используйте Postman-коллекции из папки `postman/` для тестирования API

### Альтернативный способ запуска

Вы можете собрать все модули одной командой из корня проекта:

```bash
mvn clean install
```

Затем запускать каждый сервис отдельно, как описано выше.

## Архитектура проекта

Проект использует микросервисную архитектуру, где каждый сервис:
- Имеет свою базу данных
- Может разрабатываться и масштабироваться независимо
- Взаимодействует с другими сервисами через:
  - **OpenFeign** — для синхронных HTTP-вызовов
  - **RabbitMQ** — для асинхронной обработки событий и уведомлений

## Технологический стек

- **Java 17**
- **Spring Boot 3.1.3**
- **Spring Cloud** (Eureka, Config Server, Gateway)
- **Spring Security** с OAuth2 и Keycloak
- **PostgreSQL** — база данных
- **Liquibase** — миграции БД
- **RabbitMQ** — брокер сообщений
- **Maven** — система сборки
- **Lombok** — упрощение кода
- **JPA/Hibernate** — работа с БД
